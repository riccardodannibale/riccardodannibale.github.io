<h1>ASCON on FPGA</h1>

<p class="project-subtitle">
Experimental implementation and verification of ASCON-128 on FPGA,
with SPI communication, key management, simulated PUF logic and
pipeline optimization.
</p>

</div>


<img
class="project-cover"
src="{{ '/assets/images/projects/ascon/01.png' | relative_url }}"
alt="ASCON FPGA project">


<div class="project-section">

<h2>Overview</h2>

<p>
This experimental thesis project implements and verifies an ASCON-128
cryptographic architecture in Vivado targeting an Artix-7 100T FPGA.
</p>

<p>
The architecture integrates the cryptographic core, ASCON permutation,
SPI controller, clock management and key-selection logic between an
external key and a simulated/emulated PUF.
</p>

<p>
The PUF component is simulated/emulated and is not implemented as a
physical PUF on the FPGA board. Experimental results were obtained
through Vivado functional simulation and implementation reports.
</p>

</div>


<div class="project-section">

<h2>Architecture</h2>

<p>
The design is organized into independent Verilog modules.
</p>

<ul>
<li><code>ascon_top.v</code> — top-level integration</li>
<li><code>ascon_controller.v</code> — SPI command and control FSM</li>
<li><code>ascon_core.v</code> — main AEAD datapath</li>
<li><code>ascon_perm.v</code> — ASCON permutation</li>
<li><code>ascon_logic.v</code> — key-selection logic</li>
<li><code>puf_controller.v</code> — simulated PUF model</li>
<li><code>SPI.v</code> — SPI interface</li>
<li><code>constraints.xdc</code> — FPGA constraints</li>
<li><code>tb_nist.v</code> — functional testbench</li>
</ul>

</div>


<div class="project-section">

<h2>Hardware optimization</h2>

<p>
During the analysis of the architecture, the ASCON permutation was
identified as the main performance bottleneck.
</p>

<p>
A pipelined solution was introduced to improve the critical datapath,
with the goal of reducing latency, improving datapath balancing and
increasing the maximum theoretically achievable frequency.
</p>

<p>
This optimization represents one of the main architectural aspects
of the project because it directly targets the most expensive part
of the cryptographic processing path.
</p>

</div>


<div class="project-section">

<h2>Key management</h2>

<p>
The architecture supports two possible key sources:
</p>

<ul>
<li>External key provisioned through SPI</li>
<li>Key generated by the simulated/emulated PUF</li>
</ul>

<p>
The key-selection logic is implemented in
<code>ascon_logic.v</code>.
</p>

</div>


<div class="project-section">

<h2>PUF</h2>

<p>
The PUF included in the project is an emulated model rather than a
physical PUF implemented on the FPGA board.
</p>

<p>
It generates a deterministic response from a challenge and is used
to validate the control flow and the key-selection mechanism.
</p>

</div>


<div class="project-section">

<h2>Functional validation</h2>

<p>
The system was validated through the dedicated
<code>tb_nist.v</code> testbench.
</p>

<ul>
<li>Encryption using the simulated PUF</li>
<li>External key provisioning</li>
<li>Boundary condition tests</li>
<li>Expected versus generated authentication tag comparison</li>
</ul>

</div>


<div class="project-section">

<h2>Experimental results</h2>

<p>
The simulation successfully completed all tested scenarios.
Every scenario ended with:
</p>

<p>
<strong>SUMMARY: Tag OK (all bytes match)</strong>
</p>

<ul>
<li>PUF-based encryption passed</li>
<li>External key provisioning passed</li>
<li>External-key encryption passed</li>
<li>Boundary tests passed</li>
<li>Expected and generated tags matched</li>
</ul>

<p>
The results were obtained in Vivado simulation and implementation
flow, not on a physical FPGA board.
</p>

</div>
